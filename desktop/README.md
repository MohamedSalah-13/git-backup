# Git Backup Desktop (نسخة JavaFX)

برنامج سطح مكتب يقوم بما تقوم به سكريبتات PowerShell في جذر المستودع، لكن دون حاجة إلى تثبيت Git:
يعرض مستودعات حسابك على GitHub، تختار منها، ثم ينسخ المختار إلى ملفات ZIP (ملفات الفرع الرئيسي + التاريخ الكامل).

هذه نسخة أولى (0.1) للتجربة والتطوير، وليست جاهزة للتوزيع على العملاء بعد.

## المتطلبات

- JDK 25 أو أحدث
- Maven 3.9 أو أحدث

## التشغيل

```powershell
mvn package
java -jar target\git-backup-desktop.jar
```

أو أثناء التطوير:

```powershell
mvn javafx:run
```

النسخ بدون نافذة (للجدولة لاحقًا)، وينسخ الاختيار المحفوظ:

```powershell
java -jar target\git-backup-desktop.jar --backup
java -jar target\git-backup-desktop.jar --backup --force
java -jar target\git-backup-desktop.jar --check
```

`--check` يفحص آخر نسخة لكل مستودع بدل النسخ.
رمز الخروج: 0 نجاح، 1 فشل بعض المستودعات (أو وُجدت نسخ تالفة)، 2 تعذّر البدء.

## المثبّت

```powershell
.\packaging\build-installer.ps1
```

ينتج `target\installer\Git Backup-<الإصدار>.exe` (نحو 47MB). البرنامج المثبّت يحمل Java معه، فلا يحتاج العميل إلى Java ولا Git.
التثبيت لكل مستخدم (بدون صلاحيات مدير)، مع اختصار في قائمة ابدأ وعلى سطح المكتب، والإصدار الأحدث يستبدل الأقدم.

- يحتاج البناء إلى WiX Toolset 3.x. بدونه: `-Type app-image` ينتج مجلدًا يعمل مباشرة دون مثبّت.
- المثبّت غير موقّع رقميًا، فسيعرض Windows تحذير "ناشر غير معروف" عند العميل إلى أن تُشترى شهادة توقيع.
- لتغيير الأيقونة: عدّل الرسم في `packaging\MakeIcon.java` ثم شغّله بالأمر المكتوب في رأس الملف (كتابة الملفات في مكتبة [app-icons](https://github.com/MohamedSalah-13/app-icons) المشتركة)

### Linux و macOS

`jpackage` لا يبني إلا للنظام الذي يعمل عليه، فمثبّتا Linux و macOS يُبنيان على GitHub Actions
(`.github/workflows/packages.yml`) بنفس السكريبت `build-installer.ps1`:

- عند نشر إصدار (بعد `release.ps1`) يُبنى `GitBackup-<الإصدار>-linux-x64.deb` و `GitBackup-<الإصدار>-macos-arm64.dmg`
  و `GitBackup-<الإصدار>-macos-x64.dmg` ويُضاف كلٌّ منها إلى نفس الإصدار تلقائيًا.
- عند طلب دمج يغيّر `desktop/packaging` يُبنى الثلاثة للتجربة ويُحفظون مع التشغيل (Artifacts) دون نشر.
- يدويًا من صفحة Actions: **Run workflow**، مع وسم إصدار منشور لإضافة الملفات إليه، أو بدون وسم للتجربة فقط.

ما يختلف خارج Windows:

- رمز GitHub لا يُحفظ (الحفظ يعتمد على Windows DPAPI)، و«التشغيل مع Windows» غير متاح.
- التحديث: يظهر إشعار الإصدار الجديد وزرّ «تنزيل المثبّت»، فيُنزَّل ملف النظام نفسه (`.deb` أو `.dmg` بمعالج الجهاز) ويُفحص ثم يُفتح، ويكمل المستخدم التثبيت ويعيد تشغيل البرنامج؛ لا تثبيت تلقائي. الإصدار الذي لم تُضف إليه حزمة هذا النظام بعد لا يُعرض عليه.
- macOS يرفض إصدارًا يبدأ بصفر، فالحزمة هناك تحمل `1.x.y` بدل `0.x.y`؛ البرنامج نفسه يعرض ويقارن الرقم الحقيقي.
- ملف `.dmg` غير موقّع من Apple، فيُفتح أول مرة من **System Settings ← Privacy & Security ← Open Anyway**.

## نشر إصدار

```powershell
.\packaging\release.ps1 -DryRun       # كل شيء عدا النشر
.\packaging\release.ps1               # الوسم v<الإصدار> يجب أن يكون موجودًا وعند HEAD
.\packaging\release.ps1 -CreateTag    # ينشئ الوسم عند HEAD أولًا
.\packaging\release.ps1 -VerifyOnly   # أي إصدار يُعرض الآن على النسخ المثبّتة، ولماذا
```

ينشر الإصدار المكتوب في `pom.xml` على GitHub بحيث تجده النسخ المثبّتة: يفحص المشروع (لا تعديلات غير محفوظة،
الوسم عند HEAD، الرقم أحدث من آخر إصدار منشور)، يشغّل `build-installer.ps1`، يرفع المثبّت باسم
`GitBackup-<الإصدار>-setup.exe` وهو الاسم الذي يبحث عنه البرنامج، ثم يقرأ الإصدار كما يقرؤه البرنامج.

- العمل يقوم به `tools\publish-release.ps1` في نسخة من [desktop-updater](https://github.com/MohamedSalah-13/desktop-updater) بجوار هذا المستودع (أو في المسار `DESKTOP_UPDATER_HOME`).
- «ما الجديد» الذي يراه العميل يُؤخذ من `docs\release-notes\v<الإصدار>.md` إن وُجد، وإلا من قائمة الـ commits.
- النشر لا يُتراجع عنه: جرّب `-DryRun` أولًا. وإذا قال عميل إن التحديث لم يظهر فابدأ بـ `-VerifyOnly`.

## الأيقونة بجوار الساعة والنسخ التلقائي

- إغلاق النافذة لا يغلق البرنامج: يبقى بجوار الساعة. القائمة هناك: فتح، نسخ الآن، خروج.
- تشغيل البرنامج مرة ثانية يُظهر نافذة النسخة العاملة بدل فتح نسخة جديدة.
- **نسخ تلقائي يوميًا الساعة ...**: ينسخ الاختيار المحفوظ مرة في اليوم ما دام البرنامج يعمل. إن فات الموعد والبرنامج مغلق، يُنفَّذ عند فتحه في نفس اليوم.
  يبدأ الفحص بعد 90 ثانية من التشغيل ليُتاح لـ Google Drive أن يعمل، وإن تعذّر البدء يعيد المحاولة كل 10 دقائق. عند الفشل يظهر تنبيه بجوار الساعة.
- **التشغيل مع Windows** (في النسخة المثبّتة فقط): يبدأ البرنامج مخفيًا بجوار الساعة عند تسجيل الدخول. يُكتب في مفتاح `Run` للمستخدم الحالي؛ أزل العلامة قبل إلغاء تثبيت البرنامج.

إن فعّلت النسخ التلقائي هنا فألغِ المهمة المجدولة لسكريبت PowerShell (`install-schedule.ps1 -Remove`) حتى لا يعمل الاثنان على نفس المجلد.

## الحسابات

كلها من **الإعدادات ← الحسابات**. الرموز تُحفظ مشفّرة بـ Windows DPAPI، فلا يقرؤها إلا نفس مستخدم Windows على نفس الجهاز.

- **GitHub:**
  - **الدخول عبر المتصفح:** يعرض البرنامج رمزًا قصيرًا وينسخه، ويفتح `github.com/login/device`. تلصق الرمز وتوافق، فيحفظ البرنامج الدخول.
  - **رمز...:** الصق رمز وصول شخصي (Personal Access Token) بصلاحية `repo`.
  - بدون أي منهما يستخدم البرنامج تسجيل دخول GitHub CLI (`gh auth login`) إن كان مثبتًا.
- **GitLab:** عنوان الخادم (`https://gitlab.com` أو خادم الشركة) ورمز وصول شخصي بصلاحيتي `read_api` و `read_repository`.
- **Bitbucket Cloud:** بريد حساب Atlassian ورمز API بالصلاحيات `read:user:bitbucket` و `read:repository:bitbucket`.
- **مستودعات المنظمات:** عند تفعيلها تُعرض أيضًا مستودعات المنظمات (GitHub)، والمجموعات (GitLab)، ومساحات العمل (Bitbucket) التي أنت عضو فيها.

يمكن ربط أكثر من خدمة معًا، فتظهر مستودعاتها كلها في نفس القائمة. إن تعذّر الاتصال بإحداها تُعرض مستودعات الباقي، ويُكتب السبب في السجل.

مستودعات GitHub تُحفظ كما كانت في `<المجلد>\<المالك>\<المستودع>`. مستودعات الخدمات الأخرى في مجلد خاص بها:
`<المجلد>\gitlab\<المجموعة>\<المستودع>` و `<المجلد>\bitbucket\<مساحة العمل>\<المستودع>`.

> لم يُجرَّب الاتصال بـ GitLab و Bitbucket على حسابات حقيقية بعد. الكود مبني على توثيقهما الرسمي، ومختبر على أمثلة من ردودهما.

## ما يُنسخ إضافيًا (GitHub)

من **الإعدادات ← النسخ الاحتياطي ← انسخ أيضًا**، وكلها متوقفة افتراضيًا:

| الخيار | ما يُضاف داخل ملف ZIP |
|---|---|
| الـ Issues وطلبات الدمج | `issues\issues.json` و `comments.json` و `review-comments.json` كما يعيدها GitHub API |
| الـ Wiki | `<المستودع>.wiki.bundle` بكامل تاريخ الـ wiki (`git clone` يستعيده) |
| الإصدارات | `releases\releases.json` |
| ملفات الإصدارات | الملفات المرفقة بكل إصدار في `releases\<tag>\` (قد تكون كبيرة) |

تغيير الـ Issues أو الإصدارات أو الـ wiki يكفي لعمل نسخة جديدة، حتى بدون commit جديد.
تفعيل أي خيار أول مرة يُعيد نسخ مستودعات GitHub مرة واحدة.

## فحص النسخ

**الإعدادات ← الفحص والإشعارات ← افحص ملفات النسخ بانتظام** (مفعّل افتراضيًا، كل 7 أيام)، أو زر **افحص الآن**.

يقرأ آخر نسخة ZIP لكل مستودع بالكامل:
- كل ملف داخلها يُقرأ حتى آخره، فتُكتشف أي بايتات تالفة (CRC، أو رمز التحقق في الملفات المشفرة).
- ملفات التاريخ (`.bundle`) تُحمَّل في مستودع فارغ للتأكد أن كل الـ commits سليمة.

النسخة التالفة أو المفقودة تظهر في السجل وفي تنبيه. يصلحها نسخ جديد مع خانة "إعادة النسخ حتى لو لم يتغير شيء".
إذا كان مجلد الحفظ على Google Drive، يحمّل الفحص الملفات منه.

## الإشعارات والسجل

- **إشعارات Windows** تظهر بجوار الساعة عند انتهاء النسخ أو الفحص: دائمًا، أو عند المشاكل فقط، أو أبدًا.
  لا تظهر لعملية بدأتها بنفسك والنافذة أمامك.
- زر **السجل** في أعلى النافذة يعرض آخر 300 عملية نسخ وفحص: النوع، والمدة، والنتيجة، ونتيجة كل مستودع.
  زر "فتح مجلد السجلات" يفتح ملفات السجل الشهرية الكاملة.

## الاستعادة

زر "استعادة..." يعرض كل المستودعات التي لها نسخ في مجلد الحفظ (حتى المحذوفة من GitHub)، ثم تختار النسخة والمجلد:

- **المستودع كاملًا:** نسخة عمل عادية بكل الـ commits والفروع والـ tags، و`origin` يشير إلى عنوانه الأصلي (GitHub أو GitLab أو Bitbucket).
- **الملفات فقط:** ملفات الفرع الرئيسي بدون تاريخ.

يُنشأ مجلد جديد باسم المستودع داخل المجلد المختار، وإن كان موجودًا وفيه ملفات تُرفض الاستعادة ولا يُستبدل شيء.
الاستعادة تعمل من ملفات ZIP وحدها، فلا تحتاج اتصالًا بـ GitHub ولا تسجيل دخول. رفع المستودع المستعاد إلى GitHub يتم يدويًا (`git push`).

## التشفير

خانة "تشفير النسخ" تحمي ملفات ZIP الجديدة بكلمة سر (AES-256 بصيغة ZIP القياسية)، فتُفتح أيضًا ببرامج مثل 7-Zip و WinRAR بنفس كلمة السر.

- كلمة السر تُحفظ على الجهاز مشفّرة بـ Windows DPAPI ليعمل النسخ دون سؤال. هذه نسخة للراحة فقط: **إن نسيت كلمة السر وضاع الجهاز فلا يمكن فتح النسخ.** احتفظ بها في مكان آمن.
- المحتوى مشفّر، لكن **أسماء الملفات داخل ZIP تبقى ظاهرة**.
- عند تفعيل التشفير يُعاد نسخ كل مستودع مرة واحدة حتى لو لم يتغير. النسخ الأقدم غير المشفرة تبقى إلى أن تخرج من عدد النسخ المحفوظة، أو احذفها يدويًا.
- تغيير كلمة السر يسري على النسخ الجديدة فقط. عند استعادة نسخة أقدم يطلب البرنامج كلمة سرّها.
- إن كان التشفير مفعّلًا ولا توجد كلمة سر محفوظة يتوقف النسخ بخطأ، ولا يكتب ملفات غير مشفرة.
- سكريبتات PowerShell لا تشفّر. لا توجّهها إلى مجلد حفظ تريده مشفّرًا.

## التوافق مع نسخة PowerShell

النسختان تكتبان نفس `backup-state.json` ونفس أسماء ملفات ZIP وبنفس حساب "البصمة"،
فإن وجّهت البرنامج إلى نفس مجلد الحفظ يكمل من حيث توقفت السكريبتات دون إعادة نسخ.

لا تشغّل النسختين على نفس مجلد الحفظ في الوقت نفسه.

سكريبتات PowerShell تنسخ من GitHub فقط، ولا تعرف الـ Issues والـ Wiki والإصدارات.
تحافظ على سطور GitLab و Bitbucket في `backup-state.json`، لكنها تكتب لكل منها في سجلها أنه "لم يعد في الحساب".

## أين يحفظ البرنامج ملفاته

`%LOCALAPPDATA%\GitBackupDesktop`: الإعدادات (`config.json`)، الرموز المشفّرة، نسخ محلية للمستودعات (`mirrors`) لتسريع التحديثات، والسجلات (`logs`)، وسجل العمليات (`history.json`).
يمكن تغيير المكان بمتغير البيئة `GITBACKUP_HOME`.

## بنية الكود

| الحزمة | المحتوى |
|---|---|
| `com.gitbackup.backup` | محرك النسخ (JGit) وطبقة الخدمة |
| `com.gitbackup.github` | الاتصال بـ GitHub API، والدخول عبر المتصفح، وتخزين الرمز |
| `com.gitbackup.hosts` | واجهة مشتركة للخدمات، و GitLab و Bitbucket |
| `com.gitbackup.store` | قراءة وكتابة الإعدادات وملف الحالة |
| `com.gitbackup.ui` | نافذة JavaFX (عربي / إنجليزي)، سمة AtlantaFX فاتحة/داكنة، أيقونات Ikonli، ونافذة الإعدادات |

## ما لم يُنفَّذ بعد

- إعادة رفع المستودع المستعاد إلى GitHub من داخل البرنامج.
- توقيع المثبّت رقميًا، والتحديث التلقائي.
- Git LFS، ونسخ الـ Issues والـ Wiki من GitLab و Bitbucket.
- نظام التراخيص.

## للمطوّر

`-Dgitbackup.screenshot=file.png` يحفظ صورة للنافذة بعد تحميل القائمة ثم يخرج، ومع `-Dgitbackup.autorun=true` ينفّذ النسخ أولًا. يُستخدمان للفحص الآلي فقط.

## إعداد الدخول عبر المتصفح

يحتاج الدخول عبر المتصفح إلى تطبيق OAuth مسجّل على GitHub:

1. افتح GitHub ← Settings ← Developer settings ← OAuth Apps ← New OAuth App.
2. الاسم `Git Backup`، والعنوانان أي صفحة للمشروع (لا يُستخدمان في هذه الطريقة).
3. فعّل **Enable Device Flow**، ثم انسخ الـ **Client ID**. لا تحتاج Client secret.
4. ضع الـ Client ID في `CLIENT_ID` داخل `GitHubDeviceFlow.java`. الـ Client ID ليس سرًا.

للتجربة قبل ذلك: `java -Dgitbackup.githubClientId=<ID> -jar target\git-backup-desktop.jar`.
بدونه يعرض زر "الدخول عبر المتصفح" رسالة بأنه غير مُعدّ بعد.
